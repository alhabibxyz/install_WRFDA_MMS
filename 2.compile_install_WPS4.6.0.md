# Compile WPS 4.6.0 with Intel oneAPI / MMS Environment

This guide describes how to compile **WPS 4.6.0** using the same Intel oneAPI / Intel MPI environment that was successfully used to compile WRF 4.7.1.

The tested compiler environment is:

- Intel oneAPI Compiler 2022.0.2
- Intel Fortran Compiler (ifort) 2021.5.0
- Intel C Compiler (icc) 2021.5.0
- Intel MPI 2021.5.1
- WRF 4.7.1
- WPS 4.6.0
- NetCDF / NetCDF-Fortran installed under `$HOME/install_wrf/libraries`

---

## 1. Define the WRF and library directories

Use the same library directory that was used to successfully compile WRF.

```bash
export DIR=$HOME/install_wrf/libraries
export WRF_DIR=$HOME/install_wrf/WRF
```

Set the NetCDF environment:

```bash
export NETCDF=$DIR
```

Add the NetCDF executables to `PATH`:

```bash
export PATH=$NETCDF/bin:$PATH
```

Set the runtime library path:

```bash
export LD_LIBRARY_PATH=$NETCDF/lib:$LD_LIBRARY_PATH
```

For the Intel compiler libraries:

```bash
export INTEL_LIB=/opt/software/intel/oneapi/compiler/2022.0.2/linux/compiler/lib/intel64_lin
export LD_LIBRARY_PATH=$INTEL_LIB:$NETCDF/lib
```

Check:

```bash
echo "WRF_DIR=$WRF_DIR"
echo "NETCDF=$NETCDF"
echo "LD_LIBRARY_PATH=$LD_LIBRARY_PATH"
```

Expected:

```text
WRF_DIR=/home/riset_2/install_wrf/WRF
NETCDF=/home/riset_2/install_wrf/libraries
```

## 4. Check Jasper, PNG, and Zlib libraries

WPS requires external libraries for GRIB2 support. The WPS documentation lists zlib, PNG, and Jasper among the external libraries used by the build. :contentReference[oaicite:1]{index=1}

Set:

```bash
export JASPER=$DIR
export JASPERLIB=$DIR/lib
export JASPERINC=$DIR/include
```

Also define:

```bash
export ZLIB=$DIR
export ZLIBLIB=$DIR/lib
export ZLIBINC=$DIR/include

export PNG=$DIR
export PNGLIB=$DIR/lib
export PNGINC=$DIR/include
```

Check:

```bash
ls -lh $JASPERLIB
ls -lh $JASPERINC
```

For example:

```bash
ls -lh $DIR/lib/libjasper*
ls -lh $DIR/lib/libpng*
ls -lh $DIR/lib/libz*
```

# 5. Download WPS 4.6.0

Go to the WRF installation directory:

```bash
cd ~/install_wrf
```

Download WPS 4.6.0:

```bash
wget https://github.com/wrf-model/WPS/archive/refs/tags/v4.6.0.tar.gz
```

Extract:

```bash
tar -xvf v4.6.0.tar.gz
```

Rename the directory:

```bash
mv WPS-4.6.0 WPS
```

Enter the WPS directory:

```bash
cd ~/install_wrf/WPS
```

Verify:

```bash
pwd
```

Expected:

```text
/home/riset_2/install_wrf/WPS
```

# 7. Clean any previous WPS build

If WPS has been configured or compiled before:

```bash
./clean
```

If necessary:

```bash
./clean -a
```

# 8. Configure WPS

Run:

```bash
./configure
```

The configure script will display several compiler/build options.

For this Intel oneAPI / MMS environment, select the **Intel option with GRIB2 support and the dmpar configuration** corresponding to the Intel classic compiler environment.

On the tested WPS 4.6.0 environment, select:

```text
19
```

Then press `ENTER`.

> **Important:** The exact menu numbering can change between WPS versions or source trees. Always read the menu displayed by your local `./configure`. Do not blindly select a number if the displayed options differ.

---

# 9. Check configure.wps

After configuration:

```bash
grep -nE '^(WRF_DIR|FC|CC|DM_FC|DM_CC|F77|F90)' configure.wps
```

The important part is that the WPS configuration uses the same Intel classic compiler/MPI stack as the successfully compiled WRF.

The desired compiler wrappers are:

```text
mpiifort
mpiicc
```

and **not**:

```text
mpiifx
mpiicx
```

---

# 10. Adjust configure.wps for the MMS Intel environment

Open:

```bash
vi configure.wps
```

Make sure the compiler commands are consistent with the WRF build.

Use:

```text
DM_FC = mpiifort
DM_CC = mpiicc
```

If the generated configuration uses:

```text
mpif90
mpicc
```

or another compiler wrapper, replace them with the Intel MPI wrappers used by the successful WRF build:

```text
mpiifort
mpiicc
```

Do not use:

```text
mpiifx
mpiicx
```

for this particular environment.

Also verify that:

```text
WRF_DIR = /home/riset_2/install_wrf/WRF
```

points to the successfully compiled WRF directory.

# 12. Important: ar/ranlib workaround

The MMS environment has an important runtime-library issue involving the Intel `libimf.so` library.

When:

```bash
LD_LIBRARY_PATH
```

contains the Intel compiler runtime directory, system tools such as:

```text
ar
ranlib
```

may fail with:

```text
Relink `/opt/software/intel/oneapi/compiler/2022.0.2/linux/compiler/lib/intel64_lin/libimf.so'
with `/lib64/libm.so.6' for IFUNC symbol `sinf'
Segmentation fault
```

Therefore, use the same clean wrappers that were successfully used during the WRF build.

Create `ar-clean`:

```bash
mkdir -p "$HOME/bin"

cat > "$HOME/bin/ar-clean" <<'EOF'
#!/bin/bash
unset LD_LIBRARY_PATH
unset LD_PRELOAD
unset LIBRARY_PATH
exec /usr/bin/ar "$@"
EOF

chmod +x "$HOME/bin/ar-clean"
```

Create `ranlib-clean`:

```bash
cat > "$HOME/bin/ranlib-clean" <<'EOF'
#!/bin/bash
unset LD_LIBRARY_PATH
unset LD_PRELOAD
unset LIBRARY_PATH
exec /usr/bin/ranlib "$@"
EOF

chmod +x "$HOME/bin/ranlib-clean"
```

Set:

```bash
export AR="$HOME/bin/ar-clean"
export RANLIB="$HOME/bin/ranlib-clean"
```

Verify:

```bash
$AR --version | head -1
$RANLIB --version | head -1
```

Expected:

```text
GNU ar version 2.30-128.el8_10
GNU ranlib ...
```

---

# 13. Check WPS configure.wps for AR/RANLIB

Check:

```bash
grep -nE '^(AR|RANLIB)=' configure.wps
```

If `configure.wps` contains:

```text
AR = /usr/bin/ar
RANLIB = /usr/bin/ranlib
```

change them to:

```text
AR = /home/riset_2/bin/ar-clean
RANLIB = /home/riset_2/bin/ranlib-clean
```

Use the actual value of `$HOME` if it differs.

Alternatively, if the WPS build system obtains these commands from the environment, make sure these variables are exported before compiling:

```bash
export AR="$HOME/bin/ar-clean"
export RANLIB="$HOME/bin/ranlib-clean"
```

---

# 14. Compile WPS

Before compiling, verify the environment:

```bash
echo "WRF_DIR=$WRF_DIR"
echo "NETCDF=$NETCDF"
echo "JASPER=$JASPER"
echo "JASPERLIB=$JASPERLIB"
echo "JASPERINC=$JASPERINC"
echo "AR=$AR"
echo "RANLIB=$RANLIB"
```

Then compile:

```bash
./compile 2>&1 | tee compile.wps.log
```

For a cleaner and more reproducible build, it is recommended to use:

```bash
./clean
```

before recompiling after configuration changes.

---

# 15. Parallel compilation

If the serial compilation works, WPS can also be compiled with multiple jobs if supported by the generated Makefiles.

For example:

```bash
./compile -j 4 2>&1 | tee compile.wps.log
```

However, if troubleshooting a compiler or linker problem, first use:

```bash
./compile 2>&1 | tee compile.wps.log
```

A serial build is easier to diagnose because compiler errors are not interleaved.

# 18. Verify the WPS executables

Run:

```bash
./geogrid.exe
```

If no `namelist.wps` is configured yet, it may report a namelist-related error. This does not necessarily indicate a compilation failure.

The important point at this stage is that the executable starts.

Likewise:

```bash
./ungrib.exe
```

and:

```bash
./metgrid.exe
```

These programs require properly configured input data and `namelist.wps` to perform useful processing.

# 19. Final build verification

Run:

```bash
cd ~/install_wrf/WPS

ls -lh geogrid.exe
ls -lh ungrib.exe
ls -lh metgrid.exe
```

A successful installation should show all three executables.

You can also verify the links:

```bash
ls -l geogrid.exe
ls -l ungrib.exe
ls -l metgrid.exe
```

Typical output:

```text
geogrid.exe -> geogrid/src/geogrid.exe
ungrib.exe -> ungrib/src/ungrib.exe
metgrid.exe -> metgrid/src/metgrid.exe
```

# 20. Final environment

For future WPS runs, the environment can be restored with:

```bash
export DIR=$HOME/install_wrf/libraries

export WRF_DIR=$HOME/install_wrf/WRF
export NETCDF=$DIR

export JASPER=$DIR
export JASPERLIB=$DIR/lib
export JASPERINC=$DIR/include

export ZLIB=$DIR
export ZLIBLIB=$DIR/lib
export ZLIBINC=$DIR/include

export PNG=$DIR
export PNGLIB=$DIR/lib
export PNGINC=$DIR/include

export INTEL_LIB=/opt/software/intel/oneapi/compiler/2022.0.2/linux/compiler/lib/intel64_lin

export PATH=$NETCDF/bin:$PATH
export LD_LIBRARY_PATH=$INTEL_LIB:$NETCDF/lib

export AR="$HOME/bin/ar-clean"
export RANLIB="$HOME/bin/ranlib-clean"
```

Verify:

```bash
which mpiifort
which mpiicc
which nc-config
echo $WRF_DIR
echo $NETCDF
echo $LD_LIBRARY_PATH
```

Expected compiler stack:

```text
mpiifort -> Intel MPI 2021.5.1 + ifort 2021.5.0
mpiicc   -> Intel MPI 2021.5.1 + icc 2021.5.0
```

# 21. Expected final result

The WPS installation is considered successful when the following files exist and are non-zero executable binaries:

```bash
ls -lh geogrid.exe
ls -lh ungrib.exe
ls -lh metgrid.exe
```

Expected:

```text
geogrid.exe
ungrib.exe
metgrid.exe
```

At this point the WRF/WPS software stack is:

```text
WRF 4.7.1
  |
  +-- Intel ifort 2021.5.0
  +-- Intel icc 2021.5.0
  +-- Intel MPI 2021.5.1
  |
  +-- NetCDF
  +-- NetCDF-Fortran
  +-- PNetCDF
  +-- HDF5
  +-- Jasper
  +-- PNG
  +-- zlib
  |
  +-- WPS 4.6.0
       |
       +-- geogrid.exe
       +-- ungrib.exe
       +-- metgrid.exe
```

The resulting WPS files can then be used to generate the meteorological input files required by WRF's `real.exe`.
